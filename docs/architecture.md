# Архитектура гибридной прошивки OpenWrt 24 для Xiaomi Router BE3600 (RD15)

## 1. Концепция и аппаратный профиль

Проект реализует высокопроизводительную прошивку для домашнего маршрутизатора **Xiaomi Router BE3600 (RD15)** на базе современного открытого пользовательского окружения **OpenWrt 24 (ветка 24.10 / master)** с сохранением полной функциональности аппаратных кремниевых блоков SoC Qualcomm IPQ5332.

### Аппаратная спецификация платформы
* **Центральный процессор (SoC)**: Qualcomm IPQ5332 (4 ядра ARM Cortex-A7 @ 1.1 GHz).
* **Оперативная память**: 256 МБ DDR3L.
* **Постоянная память (SPI NAND Flash)**: 128 МБ (Winbond W25N01KW).
* **Сетевой коммутатор**: Motorcomm YT9215S (5-портовый Gigabit Ethernet свитч: LAN 1–3, WAN, SerDes 2.5G Uplink).
* **Трансивер 2.5G Ethernet PHY**: Две аппаратные ревизии платы:
  * Ревизия A: Qualcomm QCA8081 (PHY ID `0x004dd101`, встроенный драйвер `at803x.c`).
  * Ревизия B: Motorcomm YT8821 (PHY ID `0x4f51ea19`, модуль `package/kernel/yt-phy-driver`).
* **Беспроводная подсистема (Wi-Fi 6 / 7)**:
  * 2.4 GHz: Встроенный в SoC радиомодуль IPQ5312 (2x2 MIMO, 802.11ax, полоса 20/40 МГц HE40, интерфейс `ath0`).
  * 5.0 GHz: Внешний радиомодуль Qualcomm QCN6432, подключенный по шине PCIe Gen3 (2x2 MIMO, 802.11ax/be, сверхширокая полоса 160 МГц HE160/EHT160, интерфейс `ath1`).
* **Аппаратные ускорители**:
  * Qualcomm PPE (Programmable Packet Engine) — аппаратная коммутация и NAT.
  * Qualcomm Crypto Engine (QCE 5.0) + ARM NEON Crypto — аппаратное ускорение шифрования.

## 2. Разметка флеш-памяти и ограничения хранилища

Маршрутизатор имеет два основных пользовательских тома UBI, накладывающих строгие ограничения на объём собираемой прошивки:
* **`ubi0` (~38 МБ)**: Основной системный раздел. Содержит сжатый образ только для чтения **SquashFS (ROM)** и динамический слой изменений **UBIFS overlay (`rootfs_data`)**.
  * *Критическое ограничение:* Всё, что включено в `DEFAULT_PACKAGES` базового образа, должно с запасом умещаться в этот раздел, оставляя свободное место для сохранения пользовательских настроек `/etc/config`. Крупные пакеты (`samba4`, `transmission`) исключены из базового образа.
* **`ubi1` (~20 МБ)**: Дополнительный пользовательский MTD-раздел. Монтируется в `/data` и может использоваться для установки сторонних пакетов через `opkg -d data`.

## 4. Профили сборки: `prebuild` vs `qsdk`

В сборочной конфигурации `target/linux/ipq53xx/image/rd15.mk` поддерживаются два параллельных целевых устройства:

1. **`xiaomi-rd15-prebuild` (Сборка с предсобранным ядром):**
   * Образ ядра копируется непосредственно из стоковой прошивки: `target/linux/ipq53xx/rd15/kernel`.
   * Пакет `nvram-vendor` обращается к закрытому символьному устройству `/dev/nvram`.
   * Преимущество: минимальное время компиляции, идеальная точность монолитного блоба вендора.

2. **`xiaomi-rd15-qsdk` (Сборка с ядром из открытых исходников QSDK 12.4):**
   * Ядро компилируется из официального репозитория CodeLinaro (`linux-ipq-5.4`, коммит `668bf957bfdcc05253bc3767c149c258ae49f323`).
   * Собирается полноценный FIT-образ: LZMA-сжатое ядро + скомпилированное дерево устройств `ipq5332-rd15.dtb` (loadaddr `0x40008000`).
   * В состав включаются нативный `uboot-envtools` и оптимизированный `nvram-env`.
   * Преимущество: полная прозрачность, возможность модификации ядра и добавления новых подсистем.

## 5. Механизм изоляции вендорного окружения (`ld-vendor`)

Для устранения конфликтов между современным окружением OpenWrt 24 (Musl libc 1.2.5, OpenSSL 3.x) и закрытыми стоковыми бинарниками Qualcomm (GLIBC / Musl старых версий, OpenSSL 1.1) реализован механизм динамического ELF-версионирования:

1. **Изолированный загрузчик**: Путь `PT_INTERP` во всех исполняемых файлах вендора перенаправлен на `/lib/ld-vendor.so.1`.
2. **Префикс `v_l*`**: Все разделяемые библиотеки вендора переименованы с префиксом `v_l*`:
   * `libc.so` $\to$ `v_lc.so`
   * `libssl.so.1.1` $\to$ `v_lssl.so.1.1`
   * `libcrypto.so.1.1` $\to$ `v_lcrypto.so.1.1`
   * `libnl-3.so.200` $\to$ `v_lnl-3.so.200`
   * `libgcc_s.so.1` $\to$ `v_lgcc_s.so.1`
3. **Патчинг ELF-заголовков**: В бинарниках вендора поля `DT_SONAME` и `DT_NEEDED` модифицированы скриптом `vendor_scripts/patch_package.py`. Это гарантирует, что закрытые процессы не загружают системные библиотеки OpenWrt 24 и работают в изолированном пространстве адресов.

## 6. Беспроводной стек Wi-Fi 6 / 7 (Qualcomm Direct Connect)

### 6.1. Архитектура радиоинтерфейсов

| Радиомодуль | Чипсет | Шина | VAP-интерфейс | PHY | Параметры и стандарты |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **2.4 GHz** | IPQ5312 (On-SoC) | AHB | `ath0` | `phy1` | 802.11b/g/n/ax, 2x2 MIMO, 20/40 МГц (HE40) |
| **5.0 GHz** | QCN6432 | PCIe Gen3 | `ath1` | `phy2` | 802.11a/n/ac/ax/be, 2x2 MIMO, 20/40/80/160 МГц (HE160/EHT160) |
| **MLD (Wi-Fi 7)**| Совместно 2.4G+5G | Внутренняя | `mld-wifi0` | `phy0` | Multi-Link Operation (агрегация диапазонов) |

### 6.2. Порядок инициализации беспроводного стека (procd)
1. **`S11load_cnss2`**: Загружает платформенный драйвер шины PCIe `ipq_cnss2.ko` с параметрами командной строки ядра и запускает системный демон `/usr/sbin/cnssdaemon -n -s` с автоматическим перезапуском (`respawn`).
2. **`S12qca-wifi`**: Загружает стек модулей Direct Connect (`mem_manager.ko`, `qdf.ko`, `umac.ko`, `qca_ol.ko`, `wifi_3_0.ko`) и плагин акселерации `ecm-wifi-plugin.ko`.
3. **`S21qca-hostapd`**: 
   * Скрипт `setup_vaps` динамически определяет имена PHY-интерфейсов и создает виртуальные точки доступа `ath0` и `ath1`.
   * Добавляет интерфейсы в мост `br-lan`.
   * Вызывает генератор `/lib/wifi/hostapd_config.sh all`, формирующий конфигурационные файлы `/var/run/hostapd-ath0.conf` и `/var/run/hostapd-ath1.conf`.
   * Запускает демоны `hostapd` и ожидает появление сокетов через функцию `wait_hostapd_sock()`.

### 6.3. Решение проблемы гонки сокетов (`wait_hostapd_sock`)
В проприетарном драйвере `qca-wifi` при создании VAP через `cfg80211` происходит асинхронная инициализация радиочипа. Если управление возвращается немедленно после `hostapd -B`, зависимые сервисы (`netifd`, скрипты LuCI) пытаются обратиться к сокету `/var/run/hostapd/athX`, который ещё не создан. В init-скрипт `qca-hostapd` внедрена функция `wait_hostapd_sock()`, опрашивающая сокет до 15 секунд и предотвращающая сбой инициализации сети.

### 6.4. Патч отображения клиентов в LuCI (`libiwinfo`)
Драйвер Qualcomm Direct Connect не возвращает список станций через стандартный вызов ядра `nl80211` (`iw dev ath0 station dump`). Для полноценного отображения списка подключенных устройств в интерфейсе LuCI (*Сеть $\to$ Беспроводная сеть*) применен патч `package/network/utils/iwinfo/patches/200-hostapd-assoclist-fallback.patch`:
* При отсутствии ответа от `nl80211` библиотека обращается напрямую к сокету hostapd.
* Производится опрос станций через вендорный протокол `STA-FIRST` / `STA-NEXT`.
* Парсятся расширенные метрики: MAC-адрес, уровень сигнала RSSI, шум, активность, битрейты TX/RX (MCS, полоса 160 МГц, NSS).

## 7. Аппаратное ускорение маршрутизации (Qualcomm PPE / NSS ECM)

Сетевой процессор IPQ5332 оснащен блоком аппаратного ускорения **Qualcomm PPE** (Programmable Packet Engine):
* **Enhanced Connection Manager (`ecm.ko`)**: Модуль ядра отслеживает сессии сетевых соединений (`nf_conntrack`) в хуке `NF_INET_POST_ROUTING`. При квалификации сессии ECM передает ее параметры напрямую в таблицы аппаратного коммутатора PPE.
* **Производительность**: Аппаратная маршрутизация между портами LAN (2.5G) и WAN обеспечивает полную утилизацию физического линка 2.5 Gbps (Line Rate) при околонулевой нагрузке на процессор (нагрузка CPU ~0–1%).
* **Wi-Fi оффлоад**: Модуль `ecm-wifi-plugin.ko` транслирует правила классификации FSE (Flow Search Engine) непосредственно в аппаратные дескрипторы Wi-Fi чипа, ускоряя восходящий и нисходящий трафик беспроводных клиентов.

## 8. Инициализация платформы и индикация

* **Генерация `board.json` и сетевые настройки**: Скрипт `target/linux/ipq53xx/rd15/base-files/etc/board.d/01_network` сопоставляет идентификаторы платы (`*ap-mi04.1*` и `*rd15*`), настраивая интерфейс `br-lan` со статическим IP `192.168.1.1/24` и пул DHCP `192.168.1.100`–`192.168.1.249`.
* **Светодиодная индикация (RGB LED)**: Модуль ядра `kmod-pwm-rgb` управляет трехцветным светодиодом на передней панели роутера через утилиту `/sbin/xqled` и скрипт `/etc/diag.sh` (желтый цвет при старте, синий при штатной работе, оранжевый/красный при сбоях).
* **Аппаратные кнопки**: Модуль `kmod-gpio-button-hotplug` обрабатывает нажатия кнопок `Reset` и `Mesh` (вызов скрипта `/etc/rc.button/reset` для штатного сброса настроек).

## 9. Модификации базовых системных пакетов OpenWrt 24

Для обеспечения бесшовного взаимодействия нативного пользовательского пространства OpenWrt 24 с ядром 5.4.213 и закрытыми сервисами вендора в базовые пакеты дерева `package/` были внесены следующие точечные изменения:

### 9.1. Системные демоны (`procd`, `ubus`, `netifd`, `busybox`)

1. **`procd`** (`package/system/procd/patches/001-compat-ubus-symlink.patch`):
   * Выставление корректных прав доступа `01777` на каталог `/tmp/run` при раннем монтировании в `initd/early.c`.
   * Создание симлинка `/var/run/ubus.sock -> /var/run/ubus/ubus.sock` от имени `root` при раннем старте `procd` до перехода демона `ubusd` под системного пользователя `ubus`.

2. **`ubus`** (`package/system/ubus/patches/001-compat-symlink.patch`):
   * Поддержка обратной совместимости пути сокета IPC для устаревших вендорных клиентов (`switch_ctl`, `nvram-vendor`).

3. **`netifd`** (`package/network/config/netifd/patches/`):
   * `001-fix-ifname-fixup-for-non-bridges.patch` — ограничение логики `ifname -> ports` исключительно интерфейсами сетевых мостов.
   * `002-fix-bridge-netlink-attrs.patch` — предотвращение отправки неподдерживаемых Netlink-атрибутов моста (`IFLA_BR_VLAN_FILTERING`) в ядро 5.4 без поддержки VLAN filtering и fallback на `ioctl(SIOCBRADDBR)`.

4. **`busybox` (v1.36.1-r2)**:
   * Активированы флаги `CONFIG_BUSYBOX_DEFAULT_PIE=y` и `CONFIG_BUSYBOX_DEFAULT_FEATURE_SUID=y` (обязательное требование ASLR монолитного ядра Qualcomm).
   * Включены 30 расширенных апплетов (`timeout`, `stat`, `devmem`, `watch`, `arping`, `wget`, `xz` и др.).
   * Поддержка флага `udhcpc -a` (ARP Ping для быстрой проверки доступности IP-адресов).

### 9.2. Адаптация сборочных Makefiles
* **`package/network/services/ppp/Makefile`**: Зависимость перенаправлена на нативный тулчейн, добавлен флаг `+libgcc`.
* **`package/libs/ncurses/Makefile`**: Добавлена явная сборочная зависимость `+libgcc` для `Package/libncurses`.

### 9.3. Точность смещений структур ядра QSDK 12.4 (Out-of-tree `kmod-*`)
Система сборки сабтаргета `rd15` (`target/linux/ipq53xx/rd15/kernel-build.mk`) на базе официального репозитория Qualcomm CodeLinaro QSDK 12.4 (`https://git.codelinaro.org/clo/qsdk/oss/kernel/linux-ipq-5.4.git`, коммит `668bf957bfdcc05253bc3767c149c258ae49f323`) гарантирует абсолютную бинарную точность смещений критических структур ядра:
* `net_device.netdev_ops` = 296
* `net_device.flags` = 316
* `net_device.type` = 348
* `net_device.dev_addr` = 508
* `net_device._tx` = 640
* `net_device.dev` = 816
* `sizeof(struct device)` = 456
* Модель разделения памяти ядра и юзерспейса: `VMSPLIT_2G`.

Это позволяет компилировать сторонние внешние модули ядра (`kmod-amneziawg`, `yt_switch.ko`, модули PPE) без риска сбоя ядра (Kernel Panic) и без необходимости создания искусственных ABI-патчей.
* **Изоляция хука `Kernel/Patch`**: Сабтаргет `rd15` изолирован от наложения несовместимых файлов из `generic/files`, так как ядро QSDK 12.4 уже содержит нативные 5.4-реализации `swconfig`, `mtdsplit` и платформенных подсистем Qualcomm.
