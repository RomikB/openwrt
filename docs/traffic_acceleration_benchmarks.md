# Методика и результаты тестирования аппаратного ускорения трафика (Qualcomm PPE / ECM)

Настоящий документ содержит стандартизированную методику тестирования, протокол измерений и результаты бенчмарков пропускной способности, аппаратного оффлоада Qualcomm PPE/ECM и утилизации процессорных ядер SoC IPQ5332 на маршрутизаторе **Xiaomi Router BE3600 (RD15)**.

Документ спроектирован для **регулярного повторного тестирования и сравнительного анализа** различных версий прошивок OpenWrt (QSDK 12.4 Linux 5.4, QSDK 12.5, апстримное ядро Linux 6.6, сборки с PBR/sing-box и др.).

### 1.2. Фиксируемые метрики

Для каждого тестового прогона фиксируются следующие параметры:
1. **Пропускная способность (Bitrate)**:
   * Измеряется утилитой `iperf3` (TCP, по умолчанию 10–15 секунд).
   * Режимы: одиночный поток (`-P 1`) и многопоточный стресс-тест (`-P 4`).
   * Направления:
     * **Upload**: клиент LAN/WLAN $\to$ WAN сервер (или Router $\to$ WAN).
     * **Download**: WAN сервер $\to$ клиент LAN/WLAN (флаг `-R`).
2. **Аппаратный оффлоад Qualcomm PPE / ECM**:
   * Счетчик ускоренных сессий IPv4: `/sys/kernel/debug/ecm/ecm_ppe_ipv4/accelerated_count`.
   * Счетчик ускоренных TCP-сессий: `/sys/kernel/debug/ecm/ecm_ppe_ipv4/tcp_accelerated_count`.
   * Счетчик ускоренных UDP-сессий: `/sys/kernel/debug/ecm/ecm_ppe_ipv4/udp_accelerated_count`.
   * Общее число соединений в базе: `/sys/kernel/debug/ecm/ecm_db/connection_count`.
3. **Нагрузка на центральный процессор (CPU)**:
   * Фиксируется на роутере утилитой `mpstat -P ALL 1 <T>` параллельно с тестом.
   * Показатели: суммарный CPU `%all` (`%sys`, `%soft`, `%idle`) и раздельная нагрузка по ядрам `Core 0`, `Core 1`, `Core 2`, `Core 3`.
4. **Срез оперативной памяти (RAM Baseline)**:
   * До старта серии тестов фиксируется потребление памяти: `MemTotal`, `MemFree`, `MemAvailable`, `Buffers`, `Cached`, `Slab`, а также распределение по процессам.

### 1.3. Сценарии тестирования

| Сценарий | Описание | Ожидаемое ускорение | Роль в анализе |
| :--- | :--- | :--- | :--- |
| **0. WAN $\leftrightarrow$ Router** | Локальная терминация iperf3 на роутере | **Без PPE** (CPU 100%) | **Baseline**: максимум нагрузки CPU без оффлоада |
| **1. WAN $\leftrightarrow$ LAN 1G** | Маршрутизация через свитч YT9215S | **Аппаратный PPE** | Проверка PPE на гигабитном транзите |
| **2. WAN $\leftrightarrow$ LAN 2.5G**| Маршрутизация через порт 2.5G `eth1` | **Аппаратный PPE** | Проверка Line Rate 2.5G и кремниевого оффлоада |
| **3. WAN $\leftrightarrow$ Wi-Fi 5G**| Беспроводной мост HE160 (`ath1`) | **ecm_wifi_plugin** | Проверка разгрузки CPU при Wi-Fi маршрутизации |
| **4. WAN $\leftrightarrow$ Wi-Fi 2.4G**| Беспроводной мост HE40 (`ath0`) | **ecm_wifi_plugin** | Проверка 2.4G радиомодуля SoC IPQ5312 |

## 3. Результаты замеров производительности

### 3.1. Baseline: WAN $\leftrightarrow$ Router (Локальная терминация, без оффлоада)

В этом режиме сетевые пакеты обрабатываются напрямую центральным процессором ARM Cortex-A7 роутера без участия кремниевого акселератора Qualcomm PPE (`accelerated_count = 0`). Данный тест служит **эталоном стоимости софтверной обработки трафика**.

| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **Router $\to$ WAN** | 1 | Upload | **942 Мбит/с** | 470 | **0** | **12.1%** (87.9% idle) | 38.4% (softirq 36.0%) | 7.7% (sys 6.6%) | 2.4% | 0.1% |
| **Router $\to$ WAN** | 4 | Upload | **939 Мбит/с** | 1825 | **0** | **14.9%** (85.1% idle) | 22.7% (softirq 20.1%) | 8.0% (sys 7.5%) | 22.6% (softirq 20.7%) | 6.3% |
| **WAN $\to$ Router** | 1 | Download (`-R`)| **855 Мбит/с** | 0 | **0** | **44.3%** (55.7% idle) | 84.8% (sys 72.0%) | 0.0% | 90.0% (softirq 89.7%) | 2.2% |

#### Выводы по Baseline:
1. При локальной терминации входящего трафика (Download) центральный процессор без PPE нагружается на **44.3% – 57.2% суммарно** (до двух полных ядер Core 0 и Core 2 на 85–90% утилизированы softirq и sys).
2. Это наглядно подтверждает необходимость аппаратного оффлоада PPE: при транзитной маршрутизации LAN $\leftrightarrow$ WAN загрузка CPU должна опускаться практически до ~0%.

#### Анализ распределения нагрузки при Wi-Fi:
1. **Upload (STA $\to$ WAN)**: Основная нагрузка ложится на **Core 0 (~70–80%)**, куда привязаны MSI-прерывания PCIe шины радиомодуля QCN6432.
2. **Download (WAN $\to$ STA)**: Нагрузка делится по двум ядрам: **Core 0 (~37–39%)** обрабатывает входной WAN-поток от контроллера EDMA, а **Core 2 (~49–52%)** выполняет упаковку и передачу кадров в кольцо драйвера `umac`.

### 3.5. Тест 4: WAN 2.5G (`eth1`) $\leftrightarrow$ Wi-Fi 5 GHz (`ath1`, HE160, полоса 160 МГц)

> *Конфигурация:* WAN переключен на порт 2.5G (`eth1`, трансивер QCA8081/YT8821, линк **2500 Мбит/с**). Клиент подключен по **Wi-Fi 5 GHz HE160** (PHY rate до 2402 Мбит/с). Лимит гигабитного WAN снят, замеряется чистая производительность беспроводного моста.

| **WAN 2.5G $\to$ WLAN 5G**| 1 | Download (`-R`)| *ожидание* | - | - | - | - | - | - | - |

#### Главные выводы по связке WAN 2.5G $\leftrightarrow$ Wi-Fi 5 GHz HE160:
1. **Преодоление гигабитного барьера**: При устранении узкого горлышка 1G WAN реальная скорость беспроводного моста достигает **1.45 – 1.47 Гбит/с** с пиками до **1.61 Гбит/с (1610 Мбит/с)** в обоих направлениях.
2. **Эффективность ecm-wifi-plugin**: Пересылка полуторагигабитного беспроводного трафика между сетевым ускорителем Qualcomm PPE и радиомодулем QCN6432 загружает суммарный вычислительный бюджет SoC всего на **~22% – 28%**. Более 70% ресурсов 4-ядерного процессора остаются свободными для пользовательских задач и служб!
3. **Распределение прерываний**:
   * При Upload на 1.5 Гбит/с ядро Core 0 утилизируется на **~85–90%** (аппаратные MSI-прерывания PCIe).
   * При Download на 1.45 Гбит/с нагрузка делится: Core 0 (**~75%**) принимает поток из 2.5G WAN, Core 2 (**~35%**) передает кадры в Wi-Fi кольцо `umac`.
