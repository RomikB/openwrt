# Миграция на ядро 1.0.81 и сравнительный анализ (Xiaomi Router BE3600 / RD15)

## 1. Главный вывод (Резюме)

Патч подсистемы MTD (**`drivers/mtd/mtdcore.c`** и добавление поля в **`struct mtd_info`**) являлся **единственным фактическим функциональным изменением исходного кода** между ядрами стоковых прошивок **1.0.68** и **1.0.81**.

Все остальные подсистемы ядра (сетевой стек, Wi-Fi драйверы Qualcomm, PPE, коммутатор, планировщик, управление питанием, USB, шина SPI/QUP) в исходном коде **абсолютно идентичны**.

Миграция проекта со стока 1.0.68 на 1.0.81 была полностью проведена и валидирована на реальном устройстве: оба профиля сборки (`xiaomi-rd15-prebuild` и `xiaomi-rd15-qsdk`) работают стабильно со 100% сохранением функциональности Wi-Fi (2.4G/5G) и аппаратного оффлоада PPE.

## 3. Детализация изменения MTD Subsystem

### 3.1. Что конкретно изменили инженеры Xiaomi
В исходном коде ядра Linux 5.4.213 были изменены два файла:
1. **`include/linux/mtd/mtd.h`**:
   В структуру `struct mtd_info` добавлено 32-битное поле:
   ```c
   struct mtd_info {
       ...
       unsigned int bitflip_threshold;
   +   unsigned int max_bitflip;
       unsigned int ecc_strength;
       ...
   };
   ```
2. **`drivers/mtd/mtdcore.c`**:
   * Создан sysfs-атрибут `max_bitflip`:
     ```c
     static DEVICE_ATTR_RO(max_bitflip);
     ```
     В строковой таблице ядра появился путь `/sys/class/mtd/mtdX/max_bitflip`.
   * В функции чтения `mtd_read()` внедрено сохранение пикового количества скорректированных битовых флипов страницы.

### 3.2. Для чего это было сделано
В стоке 1.0.81 появился фоновый сборщик телеметрии:
`/etc/sp_lib/colls/sys.maxbitflip_daily.sh`:
```sh
dd if=/dev/mtd17 of=/dev/null &> /dev/null
echo $(cat /sys/class/mtd/mtd17/ecc_strength)"."$(cat /sys/class/mtd/mtd17/max_bitflip)
```
Xiaomi понадобилось в реальном времени мониторить износ и заводской уровень ECC-ошибок SPI-NAND чипов на новых аппаратных партиях маршрутизатора RD15.

## 4. Каскадный эффект: почему различались 12 модулей ядра

Изменение размера структуры `struct mtd_info` сдвинуло смещения (offsets) всех последующих полей на **+4 байта**.

По этой причине изменились ровно те **12 модулей ядра**, которые подключают заголовочный файл `<linux/mtd/mtd.h>` и работают с MTD напрямую:

1. **`bootconfig.ko`** — модуль чтения служебных партиций `0:BOOTCONFIG` и `0:BOOTCONFIG1`.
2. **`qca-ssdk.ko`** — коммутаторный стек Qualcomm SSDK (обращается к MTD для считывания калибровок и MAC-адресов).
3. **`qca-nss-ppe-bridge-mgr.ko`** — менеджер мостов акселератора PPE.
4. **`qca-nss-ppe-vlan.ko`** — менеджер VLAN акселератора PPE.
5. **`qca-nss-ppe-vxlanmgr.ko`** — менеджер VXLAN акселератора PPE.
6. **7 тестовых модулей MTD**: `mtd_oobtest.ko`, `mtd_pagetest.ko`, `mtd_readtest.ko`, `mtd_speedtest.ko`, `mtd_stresstest.ko`, `mtd_subpagetest.ko`, `mtd_torturetest.ko`.

Все остальные 222 модуля (включая Wi-Fi драйверы `qca_cproc.ko`, `qca_ol.ko`, `ath11k`, сетевые драйверы и криптографию) **побайтово идентичны**.
