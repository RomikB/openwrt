# Коммутатор Motorcomm YT9215S и сетевой стек проводных интерфейсов (Xiaomi BE3600 / RD15)

## 1. Топология проводных интерфейсов

Маршрутизатор **Xiaomi Router BE3600 (RD15)** имеет гибридную архитектуру проводной сети, сочетающую процессорный сетевой контроллер Qualcomm IPQ5332 (EDMA v2), 5-портовый гигабитный аппаратный коммутатор Motorcomm YT9215S и физически независимый порт 2.5 Gbps.

```
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│                    ТОПОЛОГИЯ ПРОВОДНОЙ СЕТИ РОУТЕРА XIAOMI BE3600 (RD15)                        │
└─────────────────────────────────────────────────────────────────────────────────────────────────┘

                              Qualcomm IPQ5332 SoC
                   ┌─────────────────────────────────────────┐
                   │  MAC dp1 (eth0) ── 1 Gbps RGMII Uplink  │
                   │  MAC dp2 (eth1) ── 2.5 Gbps SGMII/SerDes│
                   │  MDIO Bus: /soc/mdio@90000              │
                   └────────────────────┬────────────────────┘
                                        │
                ┌───────────────────────┴───────────────────────┐
                │                                               │
                ▼                                               ▼
   ┌───────────────────────────┐                 ┌───────────────────────────┐
   │ Коммутатор YT9215S (0x1D) │                 │  Трансивер 2.5G PHY       │
   │  (kmod-yt-9215s-driver)   │                 │                           │
   │  Port 0: CPU Uplink (eth0)│                 │ Ревизия A: QCA8081 (0x0C) │
   │  Port 1: LAN 1 (eth0.3)   │                 │ Ревизия B: YT8821  (0x07) │
   │  Port 2: LAN 2 (eth0.2)   │                 └─────────────┬─────────────┘
   │  Port 3: WAN   (eth0.1)   │                               │

    ┌───────────┴───────────┐                                  ▼
    ▼           ▼           ▼                          Порт LAN 4
  LAN 1       LAN 2        WAN                          (2.5 Gbps)
```

### 1.1. Особенности аппаратной топологии RD16 (версия без 2.5G порта)

В модели **Xiaomi Router BE3600 (RD16)** физический трансивер 2.5G PHY (QCA8081 / YT8821) и интерфейс `eth1` (`dp2`) отсутствуют. Все 4 проводных порта выведены напрямую на встроенные PHY гигабитного свитча Motorcomm YT9215S:

* **Port 0**: LAN 4 (`eth0.4`, VID 4, PHY ID `0x00` на внутренней шине свитча).
* **Port 1**: LAN 1 (`eth0.3`, VID 3, PHY ID `0x01`).
* **Port 2**: LAN 2 (`eth0.2`, VID 2, PHY ID `0x02`).
* **Port 3**: WAN (`eth0.1`, VID 1, PHY ID `0x03`).
* **Port 5**: CPU Uplink к IPQ5332 `eth0` (`dp1`).

В открытом драйвере `kmod-yt-9215s-driver` (патч `004-driver.patch`) реализована динамическая поддержка обеих топологий:
1. Цикл отслеживания линков в ворккью расширен: `for (port = 0; port <= 4; port++)`.
2. Функция `port_to_lan_idx` транслирует `port 0` в `LAN 4` (`case 0: return 4;`).
3. Таблица привязки интерфейсов `g_portmap[0] = "eth0.4"` инициализируется при загрузке.

## 2. Результаты реверс-инжиниринга стокового драйвера (`yt_switch.ko`)

Анализ и дизассемблирование стокового бинарного модуля Xiaomi позволили установить ключевые особенности работы свитча на данной плате:

1. **Отсутствие узла свитча в Device Tree**: В заводском дереве устройств (`dts`) нет узла коммутатора на шине MDIO. Драйвер не использует стандартный связывающий механизм `of_match_table` и `mdio_driver_register`.
2. **Аппаратный сброс по GPIO 510**: В функции инициализации драйвер напрямую захватывает вывод `gpio_request(510, "yt-hw-reset")` (соответствует пину GPIO 51 процессора IPQ5332, базовый номер 459 + 51 = 510), удерживает уровень `LOW` 20–30 мс, затем переводит в `HIGH` на 50–60 мс для аппаратного сброса чипа.
3. **Прямой поиск шины MDIO по системному пути**: Драйвер находит системную шину по жестко заданному пути `/soc/mdio@90000` через вызов `of_find_node_opts_by_path()` и получает указатель `mii_bus` через `of_mdio_find_bus()`. Все операции обмена идут по аппаратному SMI-адресу `0x1D`.
4. **Связка с ускорителем Qualcomm PPE/ECM**: Драйвер экспортирует функцию обратного вызова `portmap_get_by_vid`, которая сообщает аппаратному акселератору соответствие между идентификатором VLAN (VID) и физическим портом свитча.

## 3. Открытый драйвер свитча на ядре 5.4 (`package/kernel/yt-9215s-driver`)

В прошивке реализован полностью открытый драйвер `kmod-yt-9215s-driver`, собираемый из официального SDK Motorcomm (`https://github.com/OpenEmbeddedBSP/motorcomm-yt9215-switch-sdk.git`, коммит `d2c8d6fc721fdb7e04e815b4fe2a397a2817ee5e`).

Для адаптации открытого SDK под плату Xiaomi BE3600 разработаны 4 модульных патча:

### 3.1. Патч `001-boardprofile.patch` (Подключение шины SMI)
* **Файл:** `switch_sdk/common/boardprofile/bprofile_YT9215SC_default_demo.c`.
* **Назначение:** Привязывает функции низкоуровневого обмена `rd15_smi_read` и `rd15_smi_write` к уровню абстракции FAL (Forwarding Abstraction Layer). Устанавливает адрес свитча `phyAddr = 0x1D` и метод доступа `SWCHIP_ACC_SMI`. Активирует дескриптор портов `YT9215sc2SGFibPortDescp` (5 портов GE + высокоскоростной 2.5G SerDes Uplink на MAC 8).

### 3.2. Патч `002-enable-yt9215sc-profile.patch` (Выбор профиля платы)
* **Файл:** `switch_sdk/config/kernel_module/env.h`.
* **Решаемая проблема:** В исходном SDK при инициализации `yt_init()` возвращалась ошибка `CMM_ERR_NOT_INIT` (код 4), так как SDK выбирал первый встретившийся профиль `Board_YT9215_Default_Demo` без SMI-доступа.
* **Решение:** Дефолтный пустой профиль отключен, принудительно включен целевой профиль `Board_YT9215SC_Default_Demo=YES`.

### 3.3. Патч `003-target-yt-switch.patch` (Имя результирующего модуля)
* **Файлы:** `switch_sdk/config/kernel_module/Mk_Module`, `switch_sdk/make/Kbuild`.
* **Назначение:** Заменяет дефолтное имя собираемого бинарника `sdk.ko` на `yt_switch.ko`, обеспечивая полную совместимость с правилами автозагрузки `/etc/modules.d/57-yt_switch` и сетевым стеком OpenWrt.

### 3.4. Патч `004-driver.patch` (Основной автономный драйвер свитча)
* **Файл:** `yt9215rb_mdio_driver/yt9215rb.c`.
* Полностью переписывает логику драйвера, реализуя 8 критических подсистем:
  1. **DT-less Probe Fallback**: Выполняет аппаратный сброс по GPIO 510 и автономный поиск шины `/soc/mdio@90000`, позволяя драйверу запускаться на стоковом DTS без изменения Device Tree.
  2. **Прямой 32-битный SMI-доступ**: Реализует функции `yt_direct_smi_read` / `yt_direct_smi_write` через косвенную адресацию PHY 0x1D для управления SerDes, LED и отладки через `/proc/smi`.
  3. **Инициализация аппаратных регистров SerDes и LED (`yt_hw_setup`)**:
     * Регистры SMI: `0x000f0004`, `0x000f0008`, `0x000f0000`.
     * Аналоговые блоки SerDes PHY 0 и 1: `0x00303000 = 0x1a5`, `0x00303020 = 0x1a5`.
     * Uplink Port 5 (2.5G SerDes): принудительно 2500 Mbps, Full Duplex, Flow Control (`yt_port_mac_force_set`, регистры `0x0008008c = 0x27a`, `0x00080028 = 1`).
     * Контроллер светодиодов LED: `0xd0000 = 0x20e002`, `0xd0004..0xd001c = 0x670`.
  4. **Исправление тегирования VLAN и TPID (Root Cause потери пакетов WAN/DHCP)**:
     * *Ingress TPID Profiles:* Через функцию `yt_vlan_igrTpid_set(0, tpid)` в регистры парсера `0x210000` прописаны EtherType `0x8100` (CTAG) и `0x88a8` (STAG). Без этого свитч не распознавал 802.1Q-теги ядра Linux и отбрасывал пакеты DHCP Discover на Port 5.
     * *Egress Tag Mode Port 5 (CPU Uplink):* Принудительно установлен в `VLAN_TAG_MODE_TAGGED`.
     * *Внешние порты (1..3):* Установлены в `VLAN_TAG_MODE_UNTAGGED`, очищены маски в регистрах `0x00210010..0x0021001c`.
  5. **Интеграция с подсистемой `swconfig`**: Регистрирует виртуальный свитч `switch1` (7 портов, 4096 VLAN), реализует коллбэки PVID, линков, аппаратных счетчиков пакетов и членства портов.
  6. **Фоновый опрос линков (Carrier Tracking)**: Однопоточный ворккью `yt_switch_wq` каждую секунду опрашивает PHY-порты и передает события в сетевой стек Linux (`netif_carrier_on/off` для `eth0.1..eth0.3`) согласно таблице `/proc/portmap`.
  7. **Управляющие интерфейсы Procfs**: `/proc/smi` (чтение/запись 32-битных регистров), `/proc/mib` (аппаратные счетчики ошибок), `/proc/portmap` (динамическая привязка портов).
  8. **Аппаратный оффлоад PPE/ECM (`portmap_get_by_vid`)**: Реализует функцию обратного вызова, привязанную к символу ядра `portmap_get_by_vid` (встроенному патчем `patches-5.4/904-vendor-compat-stubs.patch`), обеспечивая кремниевую маршрутизацию 2.5 Gbps при околонулевой загрузке CPU.

## 4. Поддержка двух аппаратных ревизий 2.5G PHY (Dual-PHY Архитектура)

В маршрутизаторах Xiaomi Router BE3600 (RD15) порт LAN 4 (2.5 Gbps) подключен к интерфейсу `dp2` (`eth1`) процессора IPQ5332 по шине MDIO (`/soc/mdio@90000`). На рынке серийно представлены две аппаратные ревизии с разными чипами 2.5G трансивера:

### 4.1. Сравнительная таблица аппаратных ревизий PHY

| Параметр | Ревизия A (Qualcomm) | Ревизия B (Motorcomm) |
| :--- | :--- | :--- |
| **Чипсет PHY** | Qualcomm Atheros QCA8081 | Motorcomm YT8821 |
| **Аппаратный PHY ID** | `0x004dd101` | `0x4f51ea19` |
| **Адрес на шине MDIO** | Первичный: `0x0C` (12 decimal) | Резервный: `0x07` (7 decimal) |
| **Драйвер ядра** | Встроенный `drivers/net/phy/at803x.c` (`CONFIG_AT803X_PHY=y`) | Модуль `package/kernel/yt-phy-driver` (`yt_phy_module.ko`) |
| **Статус исходников** | Штатный драйвер ядра Linux | Открытый бэкпорт из Linux 6.12 (`motorcomm.c`) |
| **Режим интеграции** | Подхватывается PHYlib автоматически | Регистрация в PHYlib и совместимость с sysfs Xiaomi |

---

### 4.2. Адресация в Device Tree (`ipq5332-rd15.dts`)

В заводском дереве устройств сабтаргета RD15 для поддержки обеих ревизий на уровне платы предусмотрены два адреса:
* В узле интерфейса `dp2` (`eth1`):
  ```dts
  dp2 {
      device_type = "network";
      compatible = "qcom,nss-dp";
      qcom,id = <0x01>;
      reg = <0x3a500000 0x4000>;
      qcom,mactype = <0x01>;
      mdio-bus = <0x58>;
      qcom,phy-mdio-addr = <0x0c>;      /* Первичный адрес (QCA8081) */
      qcom,sec-phy-mdio-addr = <0x07>;  /* Резервный адрес (YT8821) */
      qcom,link-poll = <0x01>;
      phy-mode = "sgmii";
  };
  ```
* В узле коммутатора `qcom,port_phyinfo`:
  ```dts
  port@0 {
      port_id = <0x01>;
      phy_address = <0x0c>;
      sec_phy_address = <0x07>;
  };
  ```

### 4.3. Реализация Dual-PHY Fallback в драйверах ядра

В стандартных открытых драйверах QSDK резервные адреса изначально игнорировались, что приводило к сбою инициализации `dp2` (ошибка `-14`), циклу ошибок в SSDK и потере интерфейса `eth1` на платах Ревизии B. Для 100% совместимости обеих ревизий («из коробки») реализованы следующие решения:

1. **Fallback в драйвере `qca-nss-dp` (`patches-5.4/002-nss-dp-support-sec-phy-mdio-addr.patch`)**:
   * При разборе дерева устройств в `nss_dp_probe()` при неуспешном первичном `phy_connect()` по адресу `0x0c` драйвер считывает `qcom,sec-phy-mdio-addr` (`0x07`) и выполняет переподключение:
     ```text
     [ 4.011525] libphy: PHY 90000.mdio:0c not found
     [ 4.017066] nss-dp 3a500000.dp2: connected to secondary phy device 90000.mdio:07
     ```
   * Интерфейс `eth1` успешно создается и добавляется в сетевой мост `br-lan`.

2. **Fallback в драйвере коммутатора `qca-ssdk` (`patches-5.4/002-ssdk-support-sec-phy-address.patch`)**:
   * В функции `ssdk_dt_parse_phy_info()` считывается свойство `sec_phy_address`.
   * Если чтение `MII_PHYSID1` на первичном адресе возвращает `0xffff` (чип QCA8081 физически отсутствует), SSDK переключается на вторичный адрес:
     ```text
     [ 3.569741] ssdk_dt_parse_phy_info[678]:INFO:port 1 primary phy 0xc not responding (id=0xffff), fallback to sec_phy 0x7
     ```
   * Устраняется циклический спам `hsl_phy_phydev_get: ERROR: phy_addr 12 phydev is NULL`.

### 4.4. Синхронизация порядка автозагрузки модулей сетевого стека

Для корректной связки PHYlib и сетевых интерфейсов строго соблюдается последовательность загрузки модулей (`/etc/modules-boot.d/`), согласованная со стоковой прошивкой:
1. **`30-qca-ssdk`** — коммутатор и аппаратная подсистема SSDK.
2. **`57-yt-9215s-driver`** — открытый драйвер 5-портового гигабитного свитча YT9215S.
3. **`57-yt-phy-driver`** — драйвер 2.5G трансивера Motorcomm YT8821 (регистрирует структуру `struct phy_driver` в подсистеме phylib).
4. **`60-qca-nss-dp`** — драйвер сетевых портов MAC/NSS (параметр `AUTOLOAD` скорректирован с `31` на `60`, гарантируя наличие драйвера PHY до вызова `phy_connect()`).

---

### 4.5. Архитектура драйвера `yt-phy-driver` и предотвращение дедлока

* Открытый модуль `package/kernel/yt-phy-driver` (`yt_phy_main.c`) бэкпортирован из upstream Linux 6.12 (`drivers/net/phy/motorcomm.c`) и содержит интерфейс страниц phylib (`.read_page = yt8521_read_page`, `.write_page = yt8521_write_page`).
* В ядре Linux функция `phy_select_page()` вызывает `phy_save_page()`, которая **уже удерживает** мьютекс шины: `mutex_lock(&phydev->mdio.bus->mdio_lock)`.
* Для исключения рекурсивного взаимного блокирования (deadlock) нерекурсивного мьютекса ядра функции `yt8521_read_page` и `yt8521_write_page` используют неблокирующие примитивы `ytphy_read_ext()` и `ytphy_modify_ext()`, обеспечивая мгновенную (за 0.6 с) инициализацию сетевого стека без таймаутов.

## 5. Открытая утилита управления `yt-9215s-client`

В пакете `package/network/utils/yt-9215s-client` реализован открытый аналог закрытой вендорной утилиты `switch_ctl`:
* Написан на чистом C, скомпилирован компилятором GCC 13.3.0 и слинкован с системным Musl libc (без зависимостей от `ld-vendor`).
* Взаимодействует с драйвером свитча через `ioctl()` к устройству `/dev/yt9215s`.
* Поддерживает опрос состояния портов, считывание MIB-статистики и управление светодиодами индикации портов.

## 6. Долгосрочный план миграции: Upstream DSA (Linux 6.6+)

Главной стратегической целью развития драйвера свитча является переход на нативную архитектуру ядра Linux **DSA (Distributed Switch Architecture)** в ветке ядра 6.6+:
1. **Разработка драйвера `drivers/net/dsa/motorcomm/yt9215s.c`**:
   * Реализация интерфейса `dsa_switch_ops` (`setup`, `port_enable`, `port_bridge_join`, `port_vlan_add`).
   * Каждый порт представляется отдельным системным интерфейсом (`lan1`, `lan2`, `lan3`, `wan`).
   * Управление через стандартные Linux-команды `ip link` и `bridge vlan`.
2. **DSA-узел в Device Tree (`ipq5332-rd15.dts`)**:
   * Описание свитча на шине MDIO с привязкой CPU-порта к MAC `dp1` процессора и аппаратного сброса к GPIO 51.
3. *Условие перехода:* Разработка DSA драйвера отложена до полной адаптации под ядро 6.6 сетевого процессора Qualcomm IPQ5332 (драйверы `qca-nss-dp`, акселератор PPE и шина Wi-Fi `cnss2`).
